## User Scenarios & Testing *(mandatory)*

### User Story 1 - ایجاد Task (Priority: P1)

کاربر عنوان یک کار را وارد می‌کند و Task جدیدی ایجاد می‌شود تا بتواند آن را در فهرست پیگیری کند.

**Why this priority**: ایجاد Task ورودی اصلی چرخه‌ی Todo است و بدون آن کاربر نمی‌تواند کار جدیدی ثبت کند.

**Independent Test**: یک عنوان معتبر وارد کنید و بررسی کنید Task جدید با شناسه‌ی یکتا، همان عنوان و وضعیت TODO ایجاد شده و در فهرست دیده می‌شود.

**Acceptance Scenarios**:

1. **Given** برنامه در حال اجرا است، **When** کاربر عنوان غیرخالی وارد می‌کند، **Then** Task با شناسه‌ی یکتا و وضعیت TODO ایجاد و در فهرست نمایش داده می‌شود.
2. **Given** کاربر عنوان خالی یا فقط شامل فاصله وارد می‌کند، **When** درخواست ایجاد Task را ثبت می‌کند، **Then** Task ایجاد نمی‌شود و پیام خطای قابل فهم به زبان فارسی نمایش داده می‌شود.

### User Story 2 - مشاهده‌ی فهرست Taskها (Priority: P2)

کاربر فهرست Taskها را می‌بیند تا بتواند عنوان و وضعیت هر کار را بررسی کند.

**Why this priority**: مشاهده‌ی فهرست، راه اصلی بررسی Taskهای اولیه و Taskهای تازه ایجادشده است.

**Independent Test**: برنامه را شروع کنید و بررسی کنید حداقل سه Task نمونه دیده می‌شوند؛ سپس Task تازه‌ای اضافه کنید و حضور آن را در فهرست بررسی کنید.

**Acceptance Scenarios**:

1. **Given** برنامه تازه شروع شده است، **When** کاربر فهرست را مشاهده می‌کند، **Then** دست‌کم سه Task نمونه با id، title و status نمایش داده می‌شوند.
2. **Given** Taskها وجود دارند، **When** کاربر فهرست را مشاهده می‌کند، **Then** هر Task با id، title و یکی از وضعیت‌های TODO یا DONE نمایش داده می‌شود.

### User Story 3 - Done کردن Task (Priority: P3)

کاربر یک Task را به‌عنوان انجام‌شده علامت می‌زند تا وضعیت آن در فهرست مشخص شود.

**Why this priority**: تکمیل Task چرخه‌ی اصلی را کامل می‌کند؛ این کار پس از ایجاد و مشاهده‌ی Taskها انجام می‌شود.

**Independent Test**: یک Task موجود را انتخاب کنید، Done کنید و وضعیت آن را در فهرست بررسی کنید؛ سپس همان درخواست را دوباره انجام دهید.

**Acceptance Scenarios**:

1. **Given** Task موجود با وضعیت TODO است، **When** کاربر آن را Done می‌کند، **Then** وضعیت همان Task به DONE تغییر می‌کند.
2. **Given** Task موجود از قبل DONE است، **When** کاربر دوباره آن را Done می‌کند، **Then** درخواست خطا محسوب نمی‌شود و وضعیت آن DONE باقی می‌ماند.
3. **Given** شناسه‌ی درخواستی به هیچ Taskی تعلق ندارد، **When** کاربر آن Task را Done می‌کند، **Then** نتیجه‌ی عملیات NOT_FOUND اعلام می‌شود و هیچ Taskی تغییر نمی‌کند.

### Edge Cases

- عنوان خالی یا عنوانی که فقط از فاصله تشکیل شده باشد پذیرفته نمی‌شود.
- JSON نامعتبر یا شناسه‌ای که قالب Long ندارد با BAD_REQUEST پاسخ داده می‌شود؛ شناسه‌ی معتبر ولی ناموجود نتیجه‌ی NOT_FOUND می‌دهد.
- اجرای دوباره‌ی درخواست Done برای Task انجام‌شده موفق و بدون تغییر باقی می‌ماند.
- وضعیت Task فقط می‌تواند TODO یا DONE باشد؛ NOT_FOUND نتیجه‌ی عملیات برای Task ناموجود است و وضعیت یک Task نیست.
- هنگام شروع برنامه، فهرست شامل حداقل سه Task نمونه است؛ تعداد بیشتر مجاز است و ترتیب فهرست تضمین نمی‌شود.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: برنامه MUST امکان ایجاد Task با title غیرخالی را فراهم کند.
- **FR-002**: برنامه MUST برای هر Task یک id از نوع Long را به‌صورت سیستمی اختصاص دهد؛ idها در هر اجرای برنامه یکتا هستند و کاربر آن‌ها را تعیین نمی‌کند.
- **FR-003**: برنامه MUST وضعیت اولیه‌ی هر Task تازه را TODO قرار دهد.
- **FR-004**: برنامه MUST امکان مشاهده‌ی فهرست Taskها را فراهم کند و برای هر Task مقدار id، title و status را نمایش دهد.
- **FR-005**: برنامه MUST هنگام startup حداقل سه Task نمونه در فهرست داشته باشد.
- **FR-006**: status هر Task MUST فقط یکی از مقادیر TODO یا DONE باشد.
- **FR-007**: برنامه MUST امکان Done کردن یک Task موجود را فراهم کند و status آن را DONE قرار دهد.
- **FR-008**: Done کردن Task با status برابر DONE MUST بدون خطا انجام شود و status آن را DONE نگه دارد.
- **FR-009**: اگر Task مورد درخواست وجود نداشته باشد، برنامه MUST نتیجه‌ی عملیات را NOT_FOUND اعلام کند و داده‌ی Taskهای دیگر را تغییر ندهد.
- **FR-010**: برنامه MUST ایجاد Task با title خالی یا فقط شامل فاصله را رد کند و به کاربر خطای قابل فهم بدهد.
- **FR-011**: Login، Authentication و ذخیره‌سازی مبتنی بر Database در محدوده‌ی این Feature نیستند.
- **FR-012**: متن رابط کاربری و پیام‌های برنامه MUST به زبان فارسی باشند؛ مقادیر وضعیت Task همچنان TODO و DONE هستند.
- **FR-013**: درخواست دارای JSON نامعتبر یا شناسه‌ی Task با قالب غیرقابل‌تبدیل به Long MUST با HTTP 400 و کد BAD_REQUEST پاسخ داده شود؛ شناسه‌ی Long معتبر ولی ناموجود MUST با HTTP 404 و کد NOT_FOUND پاسخ داده شود.

### API Constraints

- ترتیب Taskها در پاسخ فهرست تضمین نمی‌شود.
- رفتار درخواست‌های هم‌زمان خارج از محدوده‌ی این پروژه‌ی آموزشی است.
- برای این نسخه SLA عملکرد، دسترس‌پذیری یا ظرفیت لازم نیست.
- نسخه‌بندی API برای نسخه‌ی اولیه لازم نیست.

### Key Entities *(include if feature involves data)*

- **Task**: یک کار قابل پیگیری با id یکتا، title اجباری و status که فقط TODO یا DONE است.
- **نتیجه‌ی عملیات**: نتیجه‌ی درخواست کاربر؛ برای درخواست Task ناموجود مقدار NOT_FOUND دارد و جزو statusهای Task نیست.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: در آزمون ایجاد، 100٪ عنوان‌های غیرخالی یک Task یکتا با همان عنوان و وضعیت TODO ایجاد می‌کنند.
- **SC-002**: در شروع هر اجرای برنامه، فهرست شامل حداقل 3 Task نمونه است و هرکدام id، title و status قابل مشاهده دارند.
- **SC-003**: در آزمون وضعیت، 100٪ Taskها فقط با یکی از دو وضعیت TODO یا DONE نمایش داده می‌شوند.
- **SC-004**: در آزمون تکمیل، Done کردن Task موجود وضعیت آن را DONE می‌کند و تکرار همان درخواست بدون خطا همان وضعیت را حفظ می‌کند.
- **SC-005**: در آزمون شناسه‌ی ناموجود، نتیجه NOT_FOUND اعلام می‌شود و هیچ Task موجودی تغییر نمی‌کند.
- **SC-006**: کاربر می‌تواند سه جریان اصلی ایجاد، مشاهده و Done کردن Task را بدون ورود به حساب یا تنظیم Database انجام دهد.

## Assumptions

- برنامه برای استفاده‌ی یک کاربر در هر اجرای فعال در نظر گرفته می‌شود؛ مدیریت چندکاربره خارج از محدوده است.
- Taskهای نمونه برای نمایش و آزمون رفتار برنامه هستند؛ عنوان دقیق آن‌ها در این Feature اهمیت ندارد.
- title شامل فاصله‌ی خالی محسوب می‌شود؛ برای سایر عنوان‌های غیرخالی، محدودیت طول یا قالبی تعیین نشده است.
- حفظ Taskها پس از پایان و شروع مجدد برنامه جزو معیارهای این Feature نیست.
- شناسه‌ی Task یک Long است که برنامه اختصاص می‌دهد و کاربر هنگام ایجاد آن را وارد نمی‌کند.
